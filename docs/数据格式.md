# 数据格式

所有 JSON 都是纯文本、可手动编辑、可放进 GitHub 当作者预设。

---

## 1. 底图 BaseMap

存放：**角色卡变量** `worldmap_v1`（跨存档共享）。
导出/导入：设置页「导出底图」「导入底图」；作者预设就是这个格式。

```jsonc
{
  "schemaVersion": 1,
  "name": "玄天界·内置骨架",
  "sourceRef": { "repo": "user/repo", "ref": "main", "url": "https://…/worldmap-base-map.json" },
  "updatedAt": "2026-09-11T00:00:00.000Z",
  "hiddenIds": [],
  "nodes": [
    {
      "id": "n1a2b3c4",                       // 由 父id + 段名 哈希得到，稳定可复现
      "name": "神都",                          // 段名
      "path": "中央神州·大周仙朝·神都",          // 全路径，用 · 连接（U+00B7）
      "parentId": "n0f3e5d6",                 // 顶层节点为 null
      "depth": 2,                             // 树深度，0 = 顶层
      "xy": [0, 0],                           // 世界坐标，神都洛阳 = (0,0)，范围 -500..500
      "kind": "city",                         // realm|region|power|city|site|room|poi
      "altitude": 0,                          // 单位「里」，上为正；可省略
      "locked": true,                         // true = 人工/AI 不得覆盖
      "source": "seed",                       // seed|preset|ai|manual|trail
      "status": "ok",                         // ok|unplaced（unplaced 显示为虚线圈）
      "note": "大周仙朝都城，太初山上的仙都"
    }
  ]
}
```

**坐标系**：**神都洛阳 = (0,0)**，是整个坐标系的原点。正东 `+x`、正南 `+y`，**向西/向北为负**，
范围 `-500 ~ 500`。按内置骨架的换算，**1 单位 ≈ 15 亿里**，玄天界方圆约 15000 亿里正好铺满 1000×1000 的方格。
（旧版底图的原点画布西北角，读取时会自动平移 `-500` 迁移到本坐标系。）

**显示层级（tier）**：由 `kind` 推出，不需要单独存字段（也可以手写 `"tier": 3` 覆盖）：

| tier | kind | 出现所需缩放 | 屏幕半径 | 标签字号 |
|---|---|---|---|---|
| 1 | realm | 0.1× | 12px | 15px |
| 2 | region | 0.32× | 9.5px | 13.5px |
| 3 | **city 与 power（宗级势力按市级处理）** | 0.85× | 8px | 12.5px |
| 4 | site / poi | 2.6× | 6px | 11.5px |
| 5 | room | 6.5× | 4.6px | 10.5px |

**区域轮廓 `shape`（可选）**：只有 `realm` / `region` 这类**一片地方**才写，值是 4~8 个顶点的数组，
渲染成虚线多边形围出范围 —— 这是「省」和「市」在视觉上唯一的分界。城市、宗门这类点状节点**不要写**。

```jsonc
{
  "name": "东极青木域",
  "kind": "region",
  "xy": [200, 0],                                     // 范围中心
  "shape": [[200,-150],[330,-80],[335,90],[200,150],[75,90],[70,-80]]
}
```

没写 `shape` 的大区，渲染端会用**它下辖所有地点的位置算一个凸包**并外扩兜底，所以老底图不用重做也有效果。
觉得吵可以到「图层」页签取消勾选「显示区域轮廓」。

**自动清洗**：加载与保存前都会跑一遍 `sanitizeNodes()` ——
剔除纯方位节点（子节点上提到祖父并重算路径）、剔除仙界子树、
合并重复点（同名 + 路径互相包含 + 坐标几乎重合）。老底图里的脏数据靠它自动迁移。

## 2. 轨迹 Trail

存放：**聊天变量** `worldmap_trail_v1`（每个存档独立）。
它是**派生数据**：随时可以由聊天记录全量重算，删了也不会丢信息。

```jsonc
{
  "schemaVersion": 1,
  "hiddenPointIds": ["12-0"],
  "points": [
    {
      "id": "12-0",                 // `${messageId}-${swipeId}`
      "messageId": 12,
      "swipeId": 0,
      "t": "元会历·3727年·正月二十·辰时初刻",
      "nodeId": "n1a2b3c4",
      "path": "中央神州·大周仙朝·神都·宫城区·慈宁宫",
      "xy": [0.2, 0.1],
      "posSrc": "ai",               // ai=用了 /地图/坐标；lookup=查表；auto=自动落点
      "kind": "move",               // move=普通移动；stay=原地；travel=跨层远行（画虚线）
      "seq": 7,                     // 单调递增的顺序号，用来在"楼层被删"时保持顺序
      "orphan": false               // true = 这一楼已不在聊天里，但轨迹仍保留它
    }
  ]
}
```

**重建规则**（`trail.ts`）：遍历所有 assistant 楼层，从 `<JSONPatch>` 里抽 `/地图` 与 `/世界/当前地点`：
坐标优先用 AI 给的，缺失则按地名查底图，再缺失就在父节点附近自动落点。
坐标越界（< -20 或 > 1020）或跳变超过 150 且不是跨层移动时会被丢弃并记入日志。

**为什么不会因为"大总结删楼"丢轨迹**：重建时按「时间+地点」给每个点认领上一版的 `seq`
（而不是按 messageId —— 删楼会让后面所有楼层号整体前移，按楼层认领会串位）；
上一版里有、这次重建没有、且楼层已经不在聊天里的点会标成 `orphan` 继续保留、继续画线。

## 3. MVU 变量 `地图`（AI 每回合写入）

```jsonc
{ "op": "replace", "path": "/地图", "value": {
  "坐标": [0.9, 0.5],
  "层级": "中央神州·大周仙朝·神都·宫城区·慈宁宫",
  "时间": "元会历·3726年·12月24日·戌时末",
  "高度": 0
} }
```

放在 `stat_data` 的**最外层**（不是 `世界` 之下）：`stat_data` 里已经存在 schema 未定义的键
（例如剧情里出现的 `中国`），证明额外顶层键会被 MVU 正常保留；同时避开 `世界` 被整体 `replace` 的风险。

## 4. 设置 MapSettings

存放：**脚本变量** `settings`（跟着脚本走）。

```jsonc
{
  "schemaVersion": 1,
  "api": { "url": "http://localhost:1234/v1", "key": "", "model": "gemini-2.5-flash-nothinking",
           "maxTokens": 8192, "temperature": 0.3 },
  "presetUrl": "",
  "autoPlaceRadius": 1,
  "defaultOpen": true,
  "showEventLayer": true,
  "showUnplaced": true
}
```

## 5. 地点串的解析规则（`path.ts` / `graph.ts`）

实测的 `世界.当前地点` 长这样（**四种描述分隔符都用过**）：

```
中央神州·大周仙朝·神都·慈宁宫·西暖阁内殿；炭盆红亮，乳羊羹热气萦绕…     ← ；分隔
中央神州·大周仙朝·神都·皇宫·慈宁宫西暖阁·窗外风雪拍打防窥阵纹…          ← 早期楼层用 · 连描述
中央神州·阵天宗外围·官道西段·双槐驿至西行官道。日头偏西…                ← 。分隔
中州东南·百花坊·外坊茶市                                               ← 无描述
```

解析流程：

1. **归一化**：`·`(U+00B7) `・`(U+30FB) `•` `‧` `．` 统一成 `·`，全角空格归一。
2. **路径别名**（`graph.ts` 的 `PATH_ALIASES`）：`洛阳` → `中央神州·大周仙朝·神都`；
   `神都·皇宫` → `神都·宫城区`；`中州东南·百花坊` → `中央神州·东南部·百花坊` 等。
3. **前缀最长匹配**：拿段数组从长到短去查已有点的 `path`，命中即认定为该节点（专治"描述用 `·` 连"的坑）。
4. **描述止损**：像 `榻上纱帐半垂`、`朱红阵纹沿檐角明灭`、`地火阵烘暖的内寝宫` 这类段，
   会被 `looksLikeDescription()` 判定为环境描写而**不建成节点**；自动建树最深到第 6 层。
5. **短后缀合并**：`慈宁宫西暖阁` 会命中已有的 `慈宁宫`（后缀不超过 3 字时按前缀归并）。
6. **未命中**：在父节点附近按向日葵螺旋自动落点，标 `status: "unplaced"`（地图上是虚线圈）。

想扩充别名，直接改 `src/worldmap/graph.ts` 里的 `SEGMENT_ALIASES` 与 `PATH_ALIASES` 两张表。
