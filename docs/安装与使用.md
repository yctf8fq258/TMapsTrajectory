# 世界舆图 · 安装与使用

> 插件名「世界舆图」。基于**酒馆助手（JS-Slash-Runner）**，已在 TauriTavern + 酒馆助手 4.9.3 上验证。

---

## 一、安装（二选一）

### 方式 A：导入现成的脚本 JSON（推荐，无需密码）

1. 打开酒馆，进入 **酒馆助手 → 脚本**（扩展面板里的「脚本库」页签）。
2. 目标选 **全局脚本库**，点 **导入**，选择本工程里的 `docs/worldmap-script.json`。
3. 导入后脚本是**默认关闭**的（酒馆助手的设定），把它右边的开关**打开**。
4. 输入框上方的快捷回复栏会出现 **「世界舆图」** 按钮，点它开窗。

> 全局脚本库的好处：切角色卡、切预设都不会重载，底图与设置跟着你走。
> 想让地图跟角色卡走，就把脚本导入到「角色脚本库」。

### 方式 B：外链加载版（可自动更新，需要你自己的仓库）

1. 把本工程推到 GitHub（公开仓库）。
2. 重新生成外链地址：
   ```bash
   node tools/release.mjs --repo 你的用户名/TMapsTrajectory --ref main
   ```
3. 在酒馆助手里**新建一个脚本**，内容只写一行：
   ```js
   import('https://testingcf.jsdelivr.net/gh/你的用户名/TMapsTrajectory@main/dist/worldmap/index.single.js')
   ```
4. 以后改进代码只要 `git push`，玩家侧自动拿到新版。

> 国内务必用 `testingcf.jsdelivr.net` 这个镜像域名，`cdn.jsdelivr.net` 在部分网络下不可达。

## 二、本地开发（改代码后酒馆里自动生效）

本机的 node 沙箱**禁止以管道 stdio 派生子进程**，所以 esbuild / webpack CLI / `tsc --watch` 都用不了。
本工程改用「TypeScript 编译器 API 进程内转译 + 自建静态服务 + 插件内自轮询热重载」，不需要任何构建器。

```bash
# 1) 启动开发服务器（默认 5500）
npm run dev

# 2) 浏览器打开 http://localhost:5500/ ，页面上会给出一整行可直接粘贴的脚本内容
```

3. 在酒馆助手里新建脚本，粘贴那一行（形如 `import 'http://localhost:5500/dist/worldmap/index.js'`）。
4. 之后**改 `src/` 下任意文件，酒馆里的地图会在 1~2 秒内自动热重载**，不用刷新页面，也不用改脚本内容。

其它命令：

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器（转译 + 静态服务 + 热重载，同时监控 `src/`） |
| `npm run typecheck` | 全量类型检查（约 3 秒） |
| `npm run selftest` | 用**真实存档**跑「地点解析 → 节点树 → 轨迹重建」的纯逻辑自测 |
| `node tools/release.mjs` | 产出单文件脚本、导入用 JSON、外链 loader、作者底图 |
| `node tools/bundletest.mjs` | 单文件产物冒烟测试（在 Node 里桩掉酒馆全局后导入） |

**本地试验台**（不需要酒馆也能调界面）：`http://localhost:5500/tools/harness.html?fresh=1&bundle=1`
用合成数据复现酒馆助手环境，右上角标题会实时输出渲染自检（节点数 / 可见数 / 轨迹点数 / SVG 元素数）。

> `?fresh=1` 会先清掉 localStorage 里的底图与布局；`&bundle=1` 加载单文件产物，不加则加载模块版。

## 三、日常使用

### 悬浮窗

| 操作 | 效果 |
|---|---|
| 拖动标题栏 | 移动窗口 |
| **拖到酒馆最左/最右侧** | **自动缩成一枚「索引标贴」式的小书签贴在边上**（30×约 150 像素，竖排「世界舆图」）；**鼠标扫过时它保持原样不变大**，**单击才把整个窗口放出来**；把它拖离边缘也恢复成普通窗口 |
| **标题栏 `»` / 侧栏左沿的细把手** | **收起右侧栏**，画布占满整个窗口；再点一次（此时是 `«` / `‹`）展开。状态会记住 |
| 右下角小三角 | 缩放窗口（尺寸记在 localStorage） |
| `⌖` | 定位到**当前地点**并下钻 |
| `⤢` | 缩放到全图 |
| 滚轮 | 以光标为中心缩放（0.2×~90×） |
| 拖拽空白处 | 平移 |
| **单击**节点 | 选中（右侧「编辑」页签显示详情） |
| **双击**节点 | 下钻到该节点（地图只显示它和它的子节点） |
| **右键**节点 | 选中并跳到「编辑」页签 |
| 面包屑 | 点任意一级回退 |
| `Esc` | 取消选中 |

### 地图的显示规则（像高德地图那样按缩放分级）

节点按类型分成 5 级，**缩放越大显示越细**：

| 级别 | 内容 | 出现所需缩放 |
|---|---|---|
| 1 界域 | 中央神州与四域 | 0.1× |
| 2 地域 | 山脉、沙漠、荒原、冰谷、森林 | 0.32× |
| 3 城池与宗门 | 神都、坊市，以及**所有宗级势力（一律按市级处理）** | 0.85× |
| 4 地点 | 具体建筑、秘境、岛屿、塔 | 2.6× |
| 5 房间 | 殿、阁、院、房 | 6.5× |

另外两条规则保证画面不糊：

- **屏幕上靠得太近（<26px）的点只画一个** —— 缩小时洛阳只剩一颗「神都」，
  放大之后宫城区 / 四区 / 六坊 / 环墟才各自散开；
- **标签按矩形避让**，压住的自动不画（选中的与当前所在地永远优先）。

### 垂直重叠怎么画

像「广寒宫」和它正下方的「北冥黑渊」这种同坐标、不同高度的点，
下方那个会被**挪到旁边**，用**蓝色虚线**连回原位，旁边标 `▲`/`▼` 表示在上或在下。

### 不会画进地图的东西

- **纯方位词**：东部/南部/西部/北部/东南部/极西/中域腹地…… 只用来算坐标，不会变成节点；
- **仙界相关**（仙域/天庭/瑶池/凌霄）：当前舞台是玄天界，整棵子树自动跳过；
- **零碎设施**：马厩、柴房、水井、后院、某某客房、某某铺子这类**没有独立地理意义的小点**，
  轨迹落点时不会为它们单独建点，会自动挂到最近的市级以上地点；
  地图布局 AI 也被明确要求不要产出这类点（生成报告里会写「丢弃无意义设施 N 个」）；
- **环境描写**（含「的」「半垂」「明灭」这类短句）；
- **重复地点**：同名 + 路径互相包含 + 坐标几乎重合 → 合并成一个。
  老底图里的脏数据会在加载时自动清理一次，状态栏会告诉你清理了多少。

### 轨迹只画到市级（默认开）

城中细节（某某客房、西暖阁、后院……）如果逐点连线，放大后就是一张蜘蛛网。
所以**默认把轨迹点归并到它最近的「市级及以上」祖先**再连线：

- 在客栈里走两步 → 看起来就是「停在客栈所在的城市」，不会有乱七八糟的短线；
- 需要看城内细节时，到 **图层** 页签取消勾选「轨迹只连到市级」即可；
- 「轨迹」页签的完整列表**不受影响**，每一楼去了哪里都照旧逐条列出。

### 侧栏五个页签

- **图层**：显示轨迹 / **轨迹只连到市级** / 层级连线 / 待定位节点；
  「环形铺开待定位节点」把自动落点的点排成一圈方便微调。
- **地点**：搜索 + 全部节点列表，单击定位、双击下钻。
- **编辑**：
  - 开启**编辑模式**后可直接**拖动节点**改位置；
  - **增点**：在画布空白处**右键或双击**，就地新增一个地点（挂在当前下钻的节点下）；
    也可用「加子节点 / 加同级 / 在视图中心新增」按钮；
  - **删点**：选中后点「删除节点」（两步确认）或按 **Delete / Backspace**（子节点一起删）；
  - 另有精确坐标输入、重命名、锁定；撤销/重做 20 步。
- **轨迹**：按回合倒序列出轨迹点，单击跳到该点、右键隐藏/恢复。
  带「留」标记的点表示**对应楼层已经不在聊天里了**（被大总结删掉或重 roll 覆盖），
  轨迹会保留它 —— 用大总结不会丢历史。
- **设置**：分成五块可折叠的小节，**不要挤在一页里**：
  1. **地图布局 AI（接口与模型）**：接口 / 密钥（密码框，点 👁 才显示）/ 模型（下拉选，也有自定义输入框）/
     上限 / 温度，每项下面都有对应的说明；
  2. **生成底图**：**「生成底图」** 一个按钮 + **「清空地图上所有地点」**（两步确认、可撤销）+
     生成结果报告；
  3. **底图来源**：作者预设网址、拉取、恢复内置骨架；
  4. **导出 / 导入**：底图 JSON / 锚点文本的文本框与按钮；
  5. **其他**：导出轨迹。

  密钥框默认是**打码**的；「获取模型列表」拉回来的模型名**在下拉里点一下就直接替换**模型框，
  不用先清空再手打。「测试连接」会连着 `/models` 一起报错细节（HTTP 码、是否密钥不对、是否跨域连不上）。

> **只保留了一个生成按钮**（原来还有「细化当前区域」「重扫全部地点」，实测很容易凭空编出无意义的小点，
> 已从界面撤掉）。键位仍然在：控制台执行 `__worldMap.runLayout('region' | 'all')` 可以跑那两档。
> 想要更细的地点，**在地图上双击下钻后手动加**更靠谱。

### 导出 / 导入（想改坐标锚点就用这个）

设置页最下面有一个文本框和四个按钮，**不需要去找下载目录**：

| 按钮 | 作用 |
|---|---|
| **导出底图 JSON** | 完整节点表（`path` + `xy` + `kind` + `locked`）→ 填进文本框。**整段复制发给 AI**，让它按你的要求批量改坐标，改完粘回来即可 |
| **导出锚点文本** | 生成一段 `地名(坐标)｜地名(坐标)｜…`，按层级分组 → **直接替换提示词里「固定锚点」那几行**（比我手写的那份更贴合你现在的底图） |
| 复制 | 把文本框内容写进剪贴板（写不了会自动帮你全选，按 Ctrl+C） |
| 存成文件 | 另存为 `.json` 到浏览器下载目录；收不到就用「复制」 |
| **从文本框导入** | 把改好的 JSON 粘回文本框后点它，底图立即替换（会先做一次清洗，可撤销） |
| 选文件 | 从本地 `.json` 读进文本框并导入 |

> 导入会**整份替换**底图。`locked: true` 与 `source: "manual"` 会被保留，AI 与作者预设依然不会覆盖它们。

### 与 AI 协作改坐标的推荐流程

1. 点「导出底图 JSON」，全选复制，发给 AI，附上要求（例如「把北冥雪原整体往北移 20 格」「让蜀山和昆仑的间距和世界书里的 300 亿里一致」）。
2. 拿回改好的 JSON，粘进文本框 → 「从文本框导入」。
3. 点「导出锚点文本」，把结果替换掉提示词里的固定锚点段，让 AI 每回合写坐标时和底图对齐。

### 地图布局 AI（让 AI 读世界书铺点）

1. 打开「设置」，填接口地址 / 密钥，点「获取模型列表」选模型
   （默认已填好本机 LM Studio 端点 `http://localhost:1234/v1`）。
   密钥是密码框，点右边的 👁 才显示；模型列表拉回来后在**下拉里点一下**就直接替换模型名。
2. 点 **「生成底图」**：只取《玄天界介绍》《地点：X》《玄天界周期性秘境》等总纲条目
   （**仙界条目整套跳过**），产出大域、主要势力、主要城池的坐标，几十秒内完成。
   正常十来条资料，**「上限」保持 16384 就够**。
3. **人工拖动过的节点会被自动锁定，AI 永远不会覆盖它们**（生成结果里会汇报「跳过锁定 N 个」）。
4. 生成用的是独立的 API 配置，**不会**污染你正文的破限提示词与字数设置。
5. 每次生成/测试连接都会在「生成底图」小节下面留一份**报告**：
   成功还是失败、用了多少条世界书条目（列出条目名）、新增/移动/跳过/丢弃各多少、模型的原始回复；
   同一份内容也会抄进「导出 / 导入」的文本框，方便复制发给我或发给 AI 讨论。
   生成失败时报告里就是具体原因（读不到世界书 / 筛不出条目 / 模型返回没法解析……），**底图一定保持原样**。
6. 想推倒重来：点 **「清空地图上所有地点」**（两步确认、可撤销）→ 再点「生成底图」。

#### 「上限」到底填多少才合理

「上限」= `max_tokens`，**只管模型一次能写多长，不影响喂进去的世界书**。

| 场景 | 建议值 |
|---|---|
| 生成底图（界面唯一那个按钮，十来条资料 → 几十行 JSON） | **16384**（默认值，够用） |
| 一次喂 100+ 条资料（`__worldMap.runLayout('all')`，输出是几百行 JSON） | **32768 ~ 65535** |

**看到「模型返回为空」几乎都是被截断了**，不是模型不行：把上限调大即可。
有些服务端自己的上限就是 65535，填得比它还大反而会被拒。

### 作者预设（底图跨存档共享 + 可托管在 GitHub）

- 底图存在**角色卡变量**里，所以同一个角色卡的所有存档共用一份；人工修正一次，处处生效。
- 导出：设置页「导出底图」得到一个 JSON，可以放到自己的 GitHub 仓库。
- 拉取：设置页填「预设」网址后点「拉取作者预设」，例如
  `https://testingcf.jsdelivr.net/gh/你的用户名/仓库@main/presets/worldmap-base-map.json`
- 合并规则：本地**锁定/人工**的节点保留，其余按预设更新，冲突会记进提示。

## 四、数据放在哪

| 数据 | 存放位置 | 说明 |
|---|---|---|
| 底图（节点与坐标） | 角色卡变量 `worldmap_v1` | 跨存档共享，跟着角色卡走 |
| 轨迹（点与线、隐藏标记） | 聊天变量 `worldmap_trail_v1` | 每个存档独立 |
| 插件设置（API、预设网址） | 脚本变量 `settings` | 跟着脚本走 |
| 窗口位置/尺寸/页签 | `localStorage` | 纯界面状态 |
| 兜底备份 | `localStorage: worldmap_local_backup` | 角色卡变量写不进去时的降级路径 |

**不会动**你现有的任何东西：不修改角色卡 PNG、不修改预设、不修改世界书；
角色卡里「卡内手机脚本」的 `phone_data` 也不会被覆盖（写入一律走 `insertOrAssignVariables` 深合并）。

## 五、排错

| 现象 | 处理 |
|---|---|
| 点按钮没反应 | 确认脚本开关已打开；到 **酒馆助手 → 工具 → 日志查看器** 看 `[世界舆图]` 开头的报错 |
| 窗口位置跑到屏幕外 | 在页面控制台执行 `localStorage.removeItem('worldmap_local_layout')` 后重新打开 |
| 底图被改乱了 | 设置页「恢复内置骨架」，或「导入底图」导入之前导出的 JSON |
| 地图一堆「待定位」虚线圈 | 正常：这些是轨迹里出现但世界书没给方位的新地点，拖一下确认位置即可（拖完自动锁定） |
| 轨迹是空的 | 用「从聊天记录重算」；若仍为空，说明这个存档的回复里还没有 `<JSONPatch>` 地点信息 |
| 轨迹看着像蜘蛛网 | 图层页签确认「轨迹只连到市级」是勾上的；取消勾选才会逐点连线 |
| 坐标看起来没动 | 城内移动在世界尺度下只有几个像素，双击城市节点下钻即可看到细节 |
| 点「测试连接」报错 | 报错文本会写在「生成底图」下面的报告里：先看接口地址是否带 `/v1`、服务是否在跑、密钥对不对；跨域被拦时浏览器控制台会有 CORS 提示 |
| 点「生成底图」报「模型返回为空」 | 输出被 `max_tokens` 截断了：把「上限」调到 32768 或 65535 再试（也可以先「清空地图上所有地点」减小体量） |
| 点「生成底图」报别的错 | 报告里会写清是**没读到世界书**、**筛不出地点类条目**还是**模型返回无法解析**；前两种是条目命名问题，可截图发我 |
| 提示「模型返回的内容无法解析」 | 换一个更听话的模型，或在设置里调低温度；插件不会半写，原图一定保留 |

在酒馆页面按 F12，控制台里有 `window.__worldMap` 可用于排查：

```js
__worldMap.state()          // 节点数 / 轨迹点数 / 当前地点
__worldMap.diagnostics()    // 渲染管线各环节的实际数量
__worldMap.refresh()        // 立即重算轨迹
__worldMap.toBaseMap()      // 当前底图对象
```
