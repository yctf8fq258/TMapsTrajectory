# 世界舆图 · WorldMap

**给酒馆助手（JS-Slash-Runner）用的世界舆图插件：把世界书里的地点铺成一张可缩放的坐标底图，再把每回合的位置连成轨迹。**

基于 [酒馆助手 JS-Slash-Runner](https://github.com/StageDog/tavern_helper) · 已在 TauriTavern + 酒馆助手 4.9.3 上验证

</div>

---

## 是什么

角色卡的世界书里写满了地点的方位与距离，但只能在脑子里拼图。这个插件把它们铺到一张**可缩放的坐标画布**上，再把每回合写进变量里的坐标连成线 —— 于是有了一个能缩放、能下钻、能自己动手改的舆图。

不绑定任何特定作品：插件只按世界书的条目名与正文抽取地点，换一本世界书就是另一张地图。

## 特性

- **三级落点** —— 优先用 AI 写进变量的坐标，其次按地名查底图，最后自动落点并标成虚线圈等人工确认
- **按缩放分级显示** —— 5 个层级逐层展开，缩小时只有大域，放大后才散出城池与殿阁
- **大区用虚线多边形围范围** —— 「州 / 域 / 国」是一片区域而不是一个点，一眼分得清「省」和「市」
- **贴边收起** —— 拖到页面边缘缩成小书签，**单击即开窗**，悬停不会乱跳
- **手工编辑** —— 拖动改坐标、增删/重命名/锁定节点，撤销 20 步
- **删楼也不丢历史** —— 被大总结删掉、被重 roll 覆盖的轨迹点会保留并继续画线
- **AI 自动铺底图** —— 用一个独立配置的模型读世界书总纲条目，一次性铺出大域、势力、城池及其边界；人工锁定过的点永不被覆盖
- **坐标世界书（省 token）** —— 插件自建一本《世界舆图·坐标表》挂到角色卡（原世界书零改动）：正文提到某地才注入该地坐标，替代预设里每轮都发的大锚点表
- **地理态势（剧情地理一致）** —— 每回合注入「当前位置 + 所在地界 + 周边距离 + 地界规则」，非本地势力在地界内公开生事需有理由，治"宗门的人跑到别宗地盘搞事"
- **零外链美术** —— 纯 CSS + 内联 SVG：深色应用外壳（QQ/微信式的侧栏导航 + 卡片设置页）中间嵌一幅纸上古地图，不请求任何外部资源

## 安装

**方式一：导入脚本 JSON** —— 酒馆助手 → 脚本 → 全局脚本库 → 导入 `docs/worldmap-script.json`，打开开关。

**方式二：外链加载（跟随仓库更新）** —— 酒馆助手里新建脚本，内容写一行：

```js
import('https://testingcf.jsdelivr.net/gh/yctf8fq258/TMapsTrajectory@main/dist/worldmap/index.single.js')
```

指向的就是本仓库的源码，改动推上来玩家侧自动拿到新版。

> ⚠️ **jsdelivr 对 `@main` 这类分支引用有 CDN 缓存**（最长 12 小时），刚推完往往拉到的还是旧文件。
> 想立刻生效：访问 `https://purge.jsdelivr.net/gh/yctf8fq258/TMapsTrajectory@main/dist/worldmap/index.single.js` 刷缓存，
> 或者把 `@main` 换成**具体的 tag / commit SHA**（也更适合正式发布）。
> 国内建议用 `testingcf.jsdelivr.net` 镜像，`cdn.jsdelivr.net` 在部分网络下不可达。

## 发布

`npm run release` 会一次生成两样东西，任选其一发给玩家：

| 产物 | 用途 |
|---|---|
| `docs/worldmap-script.json` | 直接导入酒馆助手的成品脚本 |
| `releases/loader.js` + `dist/worldmap/index.single.js` | 外链加载版（`dist/` **必须入库**，jsdelivr 直接读仓库里的文件） |

`releases/manifest.json` 里记着版本号与外链地址，`presets/worldmap-base-map.json` 是可供玩家一键拉取的作者底图。

## 开发

本工程的构建链是刻意非主流的：开发机沙箱禁止派生子进程，`esbuild` / `vite` / `webpack` CLI / `tsc --watch` 全都用不了，于是改用 **TypeScript 编译器 API 进程内转译 + 自建静态服务 + 插件内自轮询热重载**，不需要任何构建器。

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器（转译 + 静态服务 + 热重载） |
| `npm run typecheck` | 全量类型检查 |
| `npm run release` | 产出单文件脚本、导入用 JSON、外链 loader、作者底图 |
| `npm run bundletest` | 单文件产物冒烟测试 |
| `npm run sanitize-test` | 底图清洗自测 |

> 开发机另有一批**依赖本机环境**的调试工具（本地试验台、用真实存档跑的自测等），
> 与「插件能不能跑」无关，因此不随仓库发布；`package.json` 里保留了对应脚本名，
> 在完整的工作副本里可以直接用。
